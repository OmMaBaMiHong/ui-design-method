# 整页组件与风格审计

用于当前任务范围内的页面设计、改版和审计；局部任务只检查该组件与受影响调用处。不止检查标题和首屏，页尾、导航、媒体、状态与所有可见操作同样在范围内。沿用批准背景、品牌及主题，不因整理组件擅自换风格。

## 出图前：先明确每个板块的任务

逐个填写「用户要知道什么 → 展示什么真实数据 → 去哪里做什么」。榜单回答排名依据与次序，目录回答收录与检索，动态回答新增或变化，报告回答证据与结论。若相邻板块重复同一批对象、同样字段和同一操作，先提出合并或分工的可见方案；不把待评目录混成已排名记录，不擅自删掉已批准区域。

缺数据先区分未接入、正常空、加载中、请求失败、待核验；不能都写成「待收录」，不能把未评分画成零分。新设计可用紧凑入口预留未接入板块，不制造重复空卡片；已批准布局的改变仍先出图确认。

## 必填组件清单

| 审计对象 | 出图与实施必须确定的内容 |
| --- | --- |
| 板块 | 内容任务、主次顺序、标题与主入口；是否与其他板块重复 |
| 卡片与表格 | 对象类型、字段、层级、间距、边框、圆角、桌面/手机布局、共享组件与实际调用处 |
| 字体 | 标题/正文/说明/分数的字族、字号、字重、行高、最大行数及真实长中文样张 |
| 文案 | 用户能理解的名称、一句用途、状态和动作；必要评分依据直接可见，少用内部名词与重复解释 |
| 颜色 | 沿用项目语义变量；背景、内容面、文字、强调、边框、焦点和状态逐个对应；深浅主题同一角色映射 |
| 材质与层次 | 按角色区分环境底、透明通知面、稳定阅读面和轻量预览卡；透明度、模糊、边缘、高光与阴影逐项说明，不能把所有板块套成同一个实底卡片 |
| 品牌与 Logo | 全站品牌入口一致；产品真实 Logo、作者头像、作品封面、类别图标及装饰素材分别定义，不能互相冒用 |
| 图标 | 同一功能复用同一映射，统一轮廓语言、角色尺寸、光学重量和文字间隔；纯图标入口有可访问名称 |
| 图片 | 角色、比例、裁切、来源与可访问 URL；统一缺图/加载失败兜底，不把截图或 README 第一张图猜成 Logo |
| 分数与状态 | 值、单位、来源及依据标签一致；实测、源码分析、文档资料与待评明确区分；不改变上游名次 |
| 分类与 Tab | 选项映射到实际数据和展示区域；切换后标题、记录、依据与状态对应，不只改变按钮颜色；预览有数据就展示代表记录，不能只画区域入口 |
| 交互 | 点击对象与真实目的地，悬停/焦点/按下/加载/失败；拖动与点击不冲突，触摸、键盘和减少动效路径明确 |

每类确定唯一设计变量和共享实现入口。同类行为共用组件；不同内容角色共享基础样式，采用有实际差异的少量模板，不硬塞进一个万能卡片，不为尚无真实使用方搭通用框架。统一风格不等于把头像、封面、表格与图文卡做成同一种形状。

统一组件不等于统一所有材质。玻璃通知、长表格阅读面、封面卡和头像卡可共用字体、间距、颜色角色及焦点规则，但按用途保留各自透明度、边界与光线；不能用一条背景覆盖规则把已批准的玻璃面抹成实底。审图时必须能看出背景透过玻璃、表格阅读面保护文字、内外容器有主次，避免相同实底和边框层层套盒。

用户指定液态玻璃时，大面板和表格同样须体现透射与边缘光学层次；文字保护通过批准的透明度、磨砂和局部保护面实现，不擅自换成整块不透明黑底或白底。卡片收缩也须保留必要分类、用途、依据和真实入口，不能只剩名字与分数。

具体参数沿用 [visual](visual.md)、[icons](icons.md)、[interaction](interaction.md)，不另定第二套尺度。清单写入项目已有设计记录或 [执行表](../assets/execution-sheet.md)，标记沿用、待修及待确认。

## 出图与交付关卡

1. 可见画面覆盖本次全部板块，同时给出电脑和手机；同一组有代表性的组件展示项目已采用的深浅主题，并对照各角色材质与主次层级。透明区域必须在实际背景上展示透射效果，不能只写“玻璃”却画成实底。真实字段不足时明确标记，示意图不当正式实体数据。
2. 图稿核对长标题、缺 Logo、正常空与请求失败，操作入口能说清目标。生成图中的图标须映射到实际 SVG；图里没有的行为另列动作表，不能称图片能交互。
3. 用户批准后按图实施，复用原资源和共享组件，不用重新配色或改卡片迁就库组件。
4. 实施后按清单逐区截图比对；共享组件同时抽查受影响页面，深浅主题、手机、键盘与真实点击按 [verification](verification.md) 记录。审图、功能通过、视觉通过和部署分别报告。

来源与采用范围见 [sources](sources.md) 的「整页组件审计补充」。
