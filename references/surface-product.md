# 产品面：看板、控制台、后台、工作台、AI 工作台

产品界面先回答“它围着什么转”，这一个分叉决定密度、外壳与身份，再决定页面是读的还是操作的。

## 0. 先分叉

- **后台**围着一批业务对象转（订单、用户、商品、工单）：对象列表 → 详情 → 动作，密度高，身份靠字阶与反馈节奏。
- **工作台**围着一个人反复做的一件事转（每天记账、每周复盘、每次发布）：首屏就是今天要做的那件事，密度中等，身份更鲜明。
- **读的页面**（看板、报告）回答一个问题；**操作的页面**（控制台、向导、设置、审核队列）完成一个动作。同一产品里两类页面共用 token，密度与首屏各自定。

判定方法：能说出“一共有 N 个 X”就是后台/系统工作台；说不出就是个人工作台。

## 1. 定义工作台（发散模式第 1–2 步在产品面的做法）

两问就够：主对象是什么、谁在用、每天最常做什么。得到答案的同一轮就给出整套提案（首屏、模块、钩子、数据模型），让用户对着成品反应；之后每轮重发整个改进后的定义，而不是逐条回答问题。

按结构分类而非按行业，结构决定钩子、首屏、数据骨架与必备模块：

| 结构 | 围着什么转 | 首屏形态 | 钩子读什么 |
| --- | --- | --- | --- |
| cycle 周期 | 会循环的事（经期、训练周） | 当前在周期哪一天 + 下一个节点 | 周期位置 |
| ledger 账本 | 累积的记录（记账、库存） | 今日/本期合计 + 最近几条 | 本期汇总 |
| state 状态 | 一个持续变化的量（体重、进度） | 当前值 + 趋势 | 最近变化 |
| runbook 清单 | 要按步执行的事（备考、上线） | 今天的待办 + 完成率 | 剩余步骤 |
| feed 流 | 持续到来的内容 | 新增与未读 | 新增数 |
| care 照护 | 一个会反对的被照护者（孩子、父母） | 进展而非缺口 | 正向进展 |
| operation 运营 | 一批对象的日常处理 | 待处理队列 + 异常 | 待办数与异常 |
| pipeline 流水线 | 多阶段推进的对象 | 各阶段数量 + 卡住的 | 阶段滞留 |
| registry 名册 | 一批要维护的对象 | 搜索 + 最近修改 | 变更 |
| console 控制台 | 一组可操作的系统 | 状态总览 + 动作入口 | 异常状态 |
| monitor 监控 | 持续观测的指标 | 关键指标 + 告警 | 越界 |

## 2. 钩子与数据底座

每条首屏钩子写三件事：读哪个字段；**谁写这个字段**（用户录入、系统计算、外部集成、派生）；第一天没有数据时屏幕说什么。系统类工作台的写入方多数是系统或集成，用户录入只留必要的一两处。冷启动写清前三次打开分别看到什么。

首屏自上而下列出每个区块；模块（或频道）各写它做什么与 L1/L2/L3 页面树；数据模型 `entities` 列字段、写入方与关系。输入与回报平衡：用户每录一次都在首屏看到回报。写下“第二天还会打开的理由”，它必须由某个字段的变化支撑。收入接口从某个模块自然长出来（导出、高级分析、多人协作），写在 spec 的 `revenue` 里。

产出 `.workbench/spec.md`：YAML 头含 purpose、subject、roles、hook（字段与写入方）、coldStart、home（首屏自上而下）、modules（含页面树）、entities、mvp、visual、revenue；正文是给人读的中文说明和一节“给实现方”，把方法里的私有词汇翻成普通的构建指令。没有文件系统的对话场景把整份 spec 放进一个可复制块。

## 3. 读的页面：看板与报告

每个图表回答一个问题并写在标题里；指标带单位、来源与时间范围，有对比基线（上期、目标、同类）。表格列按任务排序，首列是对象身份。空数据、加载中、请求失败、待核验分别有状态，示例数据明确标注。

## 4. 操作的页面：控制台、向导、设置、审核

列表页展示对象的身份、状态与下一步动作，批量操作在选中后出现于固定位置。向导步进可回退，每步只问本步必要的信息，最后一步汇总可改。设置按用途分组、默认值可见、改动即时反馈。审核队列一屏一项，证据与决定按钮并列，决定后自动到下一项。

## 5. AI 工作台层

叠加在以上任何页面上，当 agent 在做事时：

- 主体是**运行流**而不是图表：每条运行有名称、开始时间、当前步骤、产物链接。
- 运行状态集：排队、运行中、等待输入、等待审批、成功、部分成功、失败、已取消、超时；每种状态有独立样式与下一步动作。
- **常驻停止控制**在运行期间始终可见。
- 审批卡出现在流内，附证据链接（读取的文件、调用的工具、将执行的动作），批准/拒绝/修改三个出口。
- 成本是一等回执：每次运行显示 token 与金额，累计可查。
- 人工介入点明确：哪一步可以接管、接管后怎么继续。

## 6. 密度与色彩

中性色从带色相的中性阶取，一个强调色，语义色（成功、警告、危险、信息）单独定；看板的强调色按品牌定而不默认蓝。密度三档（紧凑、标准、舒适）用同一组 token 的不同间距与行高档位实现。列表用表格还是卡片由字段数与对比需求决定：字段多且要对比用表格，对象有图且要辨识用卡片。桌面与手机参数按 [params-web](../data/params-web.json) 与 [params-h5](../data/params-h5.json)。
