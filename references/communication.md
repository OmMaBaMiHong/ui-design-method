# 把原话改成执行单

## 1. 拆成位置和操作

1. 从用户原话标出对象：哪个菜单、标题、卡片、输入或状态。
2. 找该对象的实际组件、计算样式与事件。
3. 填“当前位置/值 → 候选值 → 改动动作 → 结果检查”，继承用户已定方向。

| 原话 | 立即做的事 | 交付 |
| --- | --- | --- |
| 字体太呆，要清秀 | 同内容比较 2–3 个真实字族及轻/常规字重，量字号行高 | 样张 + 所选文件/size/weight/lineHeight |
| 图标不好看 | 找 2–3 个语义候选 SVG，配当前字体排实际尺寸 | glyph/库/variant/笔画/间隔/状态表 |
| 没液态玻璃效果 | 查透射、折射边缘、高光、内容面；逐层做局部图 | 层级/alpha/边缘宽/位移/降级 |
| 点了没反应 | 点入口看 handler、请求和 DOM；列即时/结果反馈 | 动作表 + 实际操作结果 |
| 版式和稿不一样 | 按稿量区域坐标比例，在父容器读 DOMRect | 参数/实际值/偏差/修复表 |

## 2. 术语按需检索

```sh
node "<skill目录>/scripts/term.mjs" find --q "底部按钮被黑杠挡住了" --surface h5
node "<skill目录>/scripts/term.mjs" check
```

按原话查询最多五条，选 plain/say/trap/pairs；无命中就直接描述执行动作。先交付修改或方案，再解释必要的 1–3 个术语。检索不能代替查页面原因。
