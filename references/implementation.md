# 按批准图稿逐区开发

## 1. 读基准并量值

1. 打开已批准图片，记路径、版本、页面范围、逻辑视口、主题、内容和追加修改。
2. 从执行表取字级、图标、色值、区域坐标和动作参数。只给图片时在图稿阶段量可见值；隐藏状态从原组件与真实链路补。
3. 图片与参数表有冲突时记录到具体区域；沿用最新明确确认，不自行换方向。

## 2. 选修改位置

1. 路由 → 页面 → 布局 → 展示组件 → hook/API → 状态 → 事件，逐层填实际文件/函数。
2. 搜全部调用者：同职责展示和行为放进现有公共组件；需要改外观时保留 hook 与 handler 契约。
3. 填 token 迁移表：旧变量、选定值、使用者、主题、是否批准。
4. 列出不应丢失的当前字段：draft、attachments、selectedModel、source/record ID、scroll、权限、价格和任务状态。
5. Web/客户端内容组件共享；分别核实际 shell、窗口高度、系统标题栏和导航方式。

## 3. 完成一块再扩展

1. 在正式父容器中写该区域的 Grid/Flex、min/max、overflow，先按尺寸表让真实内容放得下。
2. 应用字体文件和字级；使用确定的 SVG 映射；应用色值、边缘与状态。
3. 数据取既有接口；加载、空、失败和统一封面/头像兜底直接复用。
4. handler 接原参数；开详情核书/团队 ID 和 section，选用核来源绑定。
5. 读 DOMRect 和计算样式，逐项对参数；排查父级继承、默认边框、伪元素、选择器覆盖、字体回退、布局最小尺寸。
6. 用正常、最长标题和缺图样本跑一遍，完成后再做下一块。

## 4. 使用测量定位偏差

| 偏差 | 先检查 |
| --- | --- |
| 字体变粗/字形不对 | 实际字体文件、字重、合成字重、回退 |
| 卡片挤压/裁切 | 父容器高度、min-width/min-height、Grid auto minimum、overflow |
| 输入框被压出窗口 | browse/dock flex 收缩与高度预算 |
| 图标显细/显大 | viewBox、原生变体、最终尺寸、有墨区域 |
| 玻璃变成纯模糊 | 光学层加载、背景透射、边缘 mask、内容保护层 |
| 真数据长短破坏布局 | 标题换行、摘要规则、固定高和异步占位 |
| 点击无结果 | handler、参数、权限、请求与结果 DOM |
| 新旧样式互相覆盖 | 样式加载顺序、选择器范围、共享 token |

开发后的交付验证用真实操作、DOM/计算样式、请求和控制台。图稿看图校对在审图阶段完成，取证方式遵循项目规则。

## 5. 写接入和交付记录

1. 执行 verification.md 的操作任务。
2. 在对照表填“区域、批准值、实际值、真实入口、结果、待办”。
3. 将确认值写回现有 token 和组件映射，跑相关工程检查。
4. 明确是设计图、隔离演示、正式本地代码、已推送还是已上线；各阶段分别给证据。
