# 查现有能力并填执行表

## 1. 定位源码入口

1. 打开项目已有 spec、路由和设计 token；先记录实际文件路径。
2. 用项目结构工具查页面和调用者；普通仓库可用：
   ```sh
   rg --files src packages | rg '(Page|Layout|Composer|Cover|Avatar|Icon|token|theme)'
   rg -n '目标路由|目标组件名|目标接口名' src packages
   ```
   按实际目录改命令；有项目结构索引时先用索引定位。
3. 从页面沿 import 追到展示组件、hook、接口封装和共享样式；再反向查组件调用者。
4. 在真实入口点一次非破坏性操作，记录 handler 名、请求方法/路径、参数字段、响应字段和结果 DOM。仅做方案时记录源码链，操作栏填“未执行”。

## 2. 把功能逐项接到新位置

在已有 spec 增量维护下表；每行是一处实际区域：

| 区域/控件 | 组件路径/调用者 | 数据字段与记录 ID | 点击函数和参数 | 结果 DOM/路由 | 要保留的状态 |
| --- | --- | --- | --- | --- | --- |
| 模板卡 | 实际组件及路径 | title/coverUrl/slug | onOpen(slug, section) | 已有详情弹层 | 选中书、来源绑定 |
| 输入区 | 实际组件及 hook | draft/attachments | onSubmit(现有 payload) | 任务/消息区域 | 草稿、模型、附件 |

表中名称是字段示例，落表时换成项目真实名称。已有封面、头像、价格权益、弹层、错误和加载组件各记一个复用位置。

## 3. 取真实内容做排版输入

1. 从现有页面或获授权接口取本次区域的真实记录，保存 ID、来源与读取时间；沿用权限。
2. 挑正常标题、最长标题、长摘要，以及已有缺图/空记录；没有缺图样本时在隔离样例里清空 URL 验证原兜底，标明样例。
3. 每个字段填：字段路径、显示格式、刷新触发、加载占位、空/失败恢复入口。
4. 取不到数据时给出实际原因、重试动作与数据缺口；图稿里的样例在交付说明标明身份。

## 4. 画具体任务线

只画本次改动涉及的真实链：
`创作首页 → 选模板 → 详情“情节脉络” → 选用 → 输入框来源出现 → 保留原草稿 → 提交`。

给每个箭头填按钮文字、handler、输入参数、成功结果、关闭/失败后的返回位置。单个按钮修改只列该按钮的状态与调用者。

## 5. 写视口和保留清单

- 视口写 CSS 像素宽高、主题、缩放、浏览器/客户端容器；短窗口至少加一档。
- 已批准稿写完整路径、对应页面、确认记录和追加修改。
- Web/客户端共享组件分别填 shell、导航和运行环境差异；布局由实际父容器决定。
- 沿用已知需求直接填表；只有无法推断且影响方案的缺项才集中问用户。
