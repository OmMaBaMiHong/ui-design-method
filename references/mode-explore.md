# 发散模式：新产品、品牌升级、新方向、局部重设计

在这个模式里探索是任务本身：先把为谁解决什么想清楚，再提出身份假设，用同条件候选打开可能，由用户在低成本阶段选版，再收敛成该产品自己的规范。按任务深度选起点：

- **新产品**：1 → 7 全跑。
- **品牌升级**：先盘点用户熟悉的名称、标志、颜色、排版、导航与核心操作，列出保留、演进、替换范围及原因，再从 3 起步并做新旧对照。
- **局部重设计**：沿用已有身份与 token，发散范围限定在涉及区域，从 4 起步，候选只针对该区域。

## 1. 战略层：为谁、完成什么事

一次只问一个问题，按顺序：这个产品给谁用（说具体的人和场景，例如“杭州妈妈每晚 8 点刷 30 分钟种草”）；他现在在凑合什么工具；用这个产品时要完成一件什么事（动词开头，例如“每周花 1 小时跟上行业热度”）；有没有对标产品。

退出条件：2–3 张人物卡（名字、场景、具体痛点）、一句话任务、2–3 个竞品及 X/Y 差异化定位轴（如 X=信息密度、Y=社交性）。产品已存在时复用既有人物与任务，直接进 2。

## 2. 旅程与结构

旅程写 6–10 步：第一次听说 → 点进来看 → 注册 → 首次使用 → 第一次正反馈 → 养成习惯 → 流失/续费，至少标 2 个流失点并各写一条对策。

结构先排信息架构：把所有页面与模块按“逛 / 看 / 发 / 搜 / 个人”分组排 3 轮；再出 2 套线框只放内容块的位置、尺寸与层级。工作台、后台、控制台类产品按[产品面](surface-product.md)第 1–2 节定义主对象、钩子、首屏与模块，其产出直接就是这一层的结构。

## 3. 身份假设

提出 2–4 个身份假设，每个写：一句话概念、情绪关键词、与用户任务的联系、可识别的视觉或交互特征、取舍、不适用场景。功能密集的工作台可以靠字阶、信息密度和反馈节奏建立身份。身份是待验证的假设，经代表页面成立后才定稿；用户已有清晰身份时直接继承。

## 4. 参考与气质卡

收集 2–3 个匹配目标的真实参考，记来源与具体学习点（阅读节奏、信息密度、图像处理、反馈方式）和不采用的部分；没有可访问参考时写明证据缺口。

用户说不清要什么时检索风格语料组气质卡：从 awesome-design-md 按人物与任务挑 3 个品牌（极简高级 → Notion / Linear / Apple；温暖信任 → Airbnb / Stripe；潮流青年 → Figma / Framer），从 awesome-design-skills 挑 3 种调性（内容站 → minimal / editorial；社交流 → bold / vibrant；专业工具 → premium / refined），组成最多 3 套气质卡，每套写第一印象、字体风格、色彩、卡片与密度、适合谁。用户挑一套后进 5。

把用户看参考时的反应转成约束：“喜欢这个细节”“这里显得廉价”翻成字重、间距、色值、图标笔画的单值。

## 5. 令牌候选与候选稿

候选数量按用户要求，用户未说时给 3 版。每版先给代码层面的令牌方案：强调色、圆角档、字阶档数、阴影档、间距栅格，附一句取舍。实质差异来自五个正交轴中至少两项不同：构图与信息组织、排版节奏、图像语言、色与材质、交互与动效表达。

候选使用同一任务、真实或明确标记的示例内容、相近视口和相同完成范围；至少展示一个核心界面，涉及品牌系统时再验一个内容密集页。候选以静态 HTML 稿放在 `design/candidate-styles/`，不碰业务代码；交互差异需要可点击原型，运动语言附短动画与静态回退。新产品可用带标记的临时 token，确认方向后纳入正式规范。

候选持续同质化时取外部随机字符串（如 `openssl rand -hex 16`）作构图或意象引子，记录种子与提示词，不展示给用户，不当作可复现保证。

## 6. 人选与独立评审

用户在候选中选版、排除或合并方向；选定后写 build brief：内容层级、布局原则、组件与状态、资产需求、约束、验收方式。

重大方向与收敛稿可加一轮独立评审：用全新上下文的评审 agent，评审包含产品与目标用户、主要任务与阶段、身份假设、必须保留的品牌资产、少量参考图、相同视口的首屏/核心区域/状态截图；候选用中性标签，排列避免固定顺序。评审提示：只据任务、身份、参考与当前视觉证据判断；先说观察到的主要任务与气质，再判断是否符合 brief；分别检查任务信息层级、身份辨识度、排版与构图、视觉一致性、细节完成度；给最多三个最影响结果的问题（区域、现象、影响、改进方向）并指出值得保留的选择；各维度可给 1–5 档辅助判断，无法观察的标未验证。实现者把主要问题转成具体修改与复核证据，复评用当前截图；先做一至两轮看是否收敛，分数是诊断线索，关键缺陷未解决即不通过。

## 7. 收敛与验证

逐项检查容器、边框、颜色、图像、动效、文案：保留帮助理解、操作、情绪表达或品牌识别的元素。文案也是设计：标题说清价值，按钮说清动作，状态说明接下来能做什么，用真实产品信息。图像与动效先写明用途再选资产、生成或代码表达，生成或下载前取得用户同意。

可访问性四项：正文对比 4.5:1、大字 3:1；所有交互件 `:focus-visible` 清晰；深色主题是完整的第二套变量；`prefers-reduced-motion` 下直接呈现结果。

真实验证：5 秒测试（这是什么、你会点哪里、它能帮你做什么）、一个 30 秒可完成的具体任务脚本、上线后 3 个漏斗指标（注册转化、首次使用完成、7 日留存）。

## 用户要跳步时

先交付一个可见的起点样子，同时补齐前置问题：“这是起点不是定论；告诉我这个产品给谁用、要完成一件什么事，两个字就行。”旅程图与无障碍检查各 10 分钟完成，在交付里顺带做掉并说明价值。

## 归档

探索产出放 `design/discovery/YYYY-MM-DD-<产品名>/`：01 人物与任务、02 旅程、03 信息架构与线框、04 可访问性清单、05 测试计划。令牌方案与规范放该产品的设计规范文件，候选稿放 `design/candidate-styles/`。
