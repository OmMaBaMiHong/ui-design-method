# 组件流程与复用（横切）

单组件任务（一个按钮、卡片、输入、标签）走本页，不启动整页流程；整页任务在开发前也按第 2–6 节核对组件。

## 1. 单组件任务

1. 查项目里同职责的组件、它的调用方与现有状态，查设计规范里的 token。
2. 定八个状态的参数并排在一张表里：默认、悬停、焦点可见、按下、禁用、加载、空、错误（表单组件加校验通过）。每态写背景、文字、边框、图标、尺寸变化与过渡时长。
3. 出预览件：在真实使用场景里展示，手机与桌面各一，项目已采用的深浅主题各一，附最长文字与缺图/缺数据形态。
4. 用户确认后实现，预览件保留为验收对照。

## 2. 先列再查

列出当前页面需要的基础组件、复合模板、数据输入与操作，查项目现有实现及所有调用方。同一能力共用组件、token 与字段契约；新页面先复用，缺的补齐再写页面。

## 3. 复用以符合批准稿为前提

现有组件外观不匹配批准稿时，修改该组件或提供符合原稿的样式变体；没有匹配组件时实现原稿要求的组件。批准稿里的表格、卡片、雷达、导航与动效按原形态实现，图稿是基准，组件向图稿对齐。

## 4. 开源优先的顺序

新增效果先查官方开源仓库与文档，核对许可、框架/SSR 兼容、键盘可达、减少动效、资源成本与是否适合批准风格。取用顺序：项目组件 → 平台与已安装依赖 → 开源代码吸收（保留出处与许可）→ 最小自写组件。组件代码许可与演示素材授权分开核对。

## 5. 组件与数据的分工

组件承担布局、裁切、图标、材质、书签/奖牌、划线/圈注、过渡与交互终态；数据承担对象身份、名称、头像/Logo、内容封面、照片集合、指标与单位、来源、时间、历史、评论与直播状态。装饰图属于组件，按角色定义；内容封面与身份头像是两个字段、两种角色。

## 6. 模板输入与状态

设计里明确模板的输入字段、图片角色、正常/空/加载/失败、少条目、长标题、缺媒体、响应式、键盘与减少动效。缺数据时保留已批准的组件结构，用真实文字封面或明确状态填充；图表只画有的数据，视频只标有的时长，直播只显示真实人数。页面采用固定模板位置还是按资料能力选型要先定下，模板变化保持推荐与排名顺序。模板用可读名称，通过同一入口接真实资料。

## 7. 缺字段追链

缺字段按 存储 → 共享序列化 → 接口契约 → 适配 → 组件 → 详情 逐层补；已有字段能表达的直接复用。图片字段可访问、保留来源与授权；接口只返回需要的公开字段。

## 8. 验收

先在真实使用场景展示正常与边界状态，沿用已批准画面。验收证据是真实路由、操作、资源加载、焦点、请求结果与同条件截图；组件测试、实页功能、视觉通过、生产发布分别记录。
